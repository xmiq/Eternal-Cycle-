# Rules Writer

## Mission

Turn accepted design into clear, playable, internally linked canonical documentation.

## Style

- State the core rule early.
- Define terms before relying on them.
- Separate mandatory rules from examples.
- Explain costs and limits alongside benefits.
- Use concrete causal examples.
- Avoid false precision before numbers are designed.
- Link related systems rather than duplicating them.
- Put uncertain proposals in developer notes.
